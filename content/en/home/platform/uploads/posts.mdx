Feed posts combine media uploads with social metadata to create rich content for structured feeds.
This process uploads media and creates the post simultaneously.

## Post Types

**Video Posts** - Upload videos with automatic poster generation and thumbnail images for feed display.

**Image Posts** - Upload standalone images optimized for various display contexts and transformations.

## Upload Process

Posts combine a media upload with publishing to a feed:

<Steps>
  <Step>
    ### Create the Upload

    Call `POST /posts/v1/projects/{project_id}/feeds/{feed_id}/posts/upload` with the content type, file name, creator ID and description.

  </Step>

  <Step>
    ### Upload Media

    `PUT` your files to the returned presigned URLs. Processing starts once the upload lands; there is no completion call.

  </Step>
</Steps>

## Request Fields

- **`content_type`** - `MEDIA_TYPE_VIDEO` or `MEDIA_TYPE_IMAGE`
- **`file_name`** - Name of your media file (e.g., "my-video.mp4")
- **`creator_id`** - Unique identifier for the user creating the post
- **`description`** - Caption for the post (up to 280 characters)
- **`video_quality`** - For videos: `VIDEO_QUALITY_BASIC`, `VIDEO_QUALITY_SHORTS` or `VIDEO_QUALITY_PRO` (see [Quality Tiers](/en/home/platform/uploads/videos/quality-tiers))

## API Examples

### Create the Upload

<Tabs items={['Video Post', 'Image Post']}>
  <Tab value="Video Post">
    ```bash
    curl -f -s -S \
      -X POST "https://api.rixl.com/posts/v1/projects/YOUR_PROJECT_ID/feeds/FD4y3QB38S/posts/upload" \
      -H "X-API-Key: YOUR_PROJECT_API_KEY" \
      -H "Content-Type: application/json" \
      --max-time 30 \
      --data '{
        "content_type": "MEDIA_TYPE_VIDEO",
        "file_name": "my-awesome-clip.mp4",
        "creator_id": "CR8y3QB38S",
        "description": "Check out this amazing view!",
        "video_quality": "VIDEO_QUALITY_SHORTS"
      }'
    ```

    **Response:**
    ```json
    {
      "post_id": "PS5IMKoFLm",
      "content_id": "VI9VXQxWXQ",
      "content_upload_url": "https://...signed-url-for-video...",
      "poster_id": "IM8y3QB38S",
      "poster_upload_url": "https://...signed-url-for-poster...",
      "upload_expires": "2026-01-01T12:00:00Z"
    }
    ```

  </Tab>

  <Tab value="Image Post">
    ```bash
    curl -f -s -S \
      -X POST "https://api.rixl.com/posts/v1/projects/YOUR_PROJECT_ID/feeds/FD4y3QB38S/posts/upload" \
      -H "X-API-Key: YOUR_PROJECT_API_KEY" \
      -H "Content-Type: application/json" \
      --max-time 30 \
      --data '{
        "content_type": "MEDIA_TYPE_IMAGE",
        "file_name": "beautiful-sunset.jpg",
        "creator_id": "CR8y3QB38S",
        "description": "Beautiful sunset from my balcony"
      }'
    ```

    **Response:**
    ```json
    {
      "post_id": "PS5IMKoFLm",
      "content_id": "IM8y3QB38S",
      "content_upload_url": "https://...signed-url-for-image...",
      "upload_expires": "2026-01-01T12:00:00Z"
    }
    ```

  </Tab>
</Tabs>

<Callout type="warn">
  This `POST` does not honour `Idempotency-Key`, so don't retry it automatically: a retry can create a second post. See
  [Retries](/en/home/platform/api-documentation/error-handling#retries).
</Callout>

### Upload Media Files

<Tabs items={['Video Upload', 'Poster Upload']}>
  <Tab value="Video Upload">
    ```bash
    curl -# -f \
      -X PUT "$CONTENT_UPLOAD_URL" \
      --upload-file "/path/to/my-awesome-clip.mp4" \
      -H "Content-Type: video/mp4" \
      --retry 3 \
      --max-time 300
    ```
  </Tab>

  <Tab value="Poster Upload">
    ```bash
    curl -# -f \
      -X PUT "$POSTER_UPLOAD_URL" \
      --upload-file "/path/to/poster-image.jpg" \
      -H "Content-Type: image/jpeg" \
      --retry 3 \
      --max-time 60
    ```
  </Tab>
</Tabs>

A `PUT` to a presigned URL replaces the same object, so retrying it is safe until `upload_expires`.

## Managing Your Posts

### Retrieving Posts

**Get a Specific Post**:

```bash
curl "https://api.rixl.com/posts/v1/projects/YOUR_PROJECT_ID/posts/PS5IMKoFLm" \
  -H "X-API-Key: YOUR_PROJECT_API_KEY"
```

**List Posts in a Feed** (see [Pagination](/en/home/platform/api-documentation/pagination)):

```bash
curl "https://api.rixl.com/posts/v1/projects/YOUR_PROJECT_ID/feeds/FD4y3QB38S/posts?pagination.limit=25&pagination.offset=0" \
  -H "X-API-Key: YOUR_PROJECT_API_KEY"
```

**List Posts by a Creator**:

```bash
curl "https://api.rixl.com/posts/v1/projects/YOUR_PROJECT_ID/feeds/FD4y3QB38S/posts/creators/CR8y3QB38S?pagination.limit=25" \
  -H "X-API-Key: YOUR_PROJECT_API_KEY"
```

Public feeds are also readable without a key at `GET /posts/v1/feeds/{feed_id}`.

### Post Operations

**Delete a Post**:

```bash
curl -f -s -S \
  -X DELETE "https://api.rixl.com/posts/v1/projects/YOUR_PROJECT_ID/posts/PS5IMKoFLm" \
  -H "X-API-Key: YOUR_PROJECT_API_KEY" \
  --max-time 30
```

<Callout type="warn">Deleting a post will permanently remove it from the feed and cannot be undone.</Callout>

## Best Practices

When working with posts and feeds, consider these recommendations for optimal performance and user experience.

**Always upload poster images** for video posts to ensure consistent loading experiences across your application.

**Use descriptive file names** to help with content organization and make debugging easier.

**Implement proper error handling** for failed uploads; retry only as described in [Retries](/en/home/platform/api-documentation/error-handling#retries).

**Consider file size limits** when uploading high-quality content to maintain good performance.
