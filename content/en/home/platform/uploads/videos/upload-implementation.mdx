## Upload Implementation

### Implementation Overview

**Two-step upload process**:

1. **Create the upload**: `POST /media/v1/projects/{project_id}/videos/upload` returns `video_id`, `video_upload_url`, `poster_upload_url` and `expires_at`.
2. **Upload the files**: `PUT` the video and a poster image to those URLs. Processing starts once the upload lands; there is no completion call.

Then [monitor the status](/en/home/platform/uploads/videos/monitoring-status) until the video is ready.

<Tabs items={['JavaScript', 'Python', 'cURL']}>
  <Tab value="JavaScript">
    ```javascript
    async function uploadVideo(projectId, video, poster, idempotencyKey = crypto.randomUUID()) {
      const init = await fetch(`https://api.rixl.com/media/v1/projects/${projectId}/videos/upload`, {
        method: "POST",
        headers: {
          "X-API-Key": process.env.RIXL_API_KEY,
          "Content-Type": "application/json",
          "Idempotency-Key": idempotencyKey,
        },
        body: JSON.stringify({name: video.name, video_quality: "VIDEO_QUALITY_PRO"}),
      });
      if (!init.ok) throw Object.assign(new Error((await init.json()).error), {status: init.status, retryAfter: init.headers.get("Retry-After")});
      const {video_id, video_upload_url, poster_upload_url} = await init.json();

      const puts = await Promise.all([
        fetch(video_upload_url, {method: "PUT", body: video}),
        fetch(poster_upload_url, {method: "PUT", body: poster}),
      ]);
      if (puts.some((r) => !r.ok)) throw new Error("upload to storage failed");
      return video_id;
    }
    ```

    ```python
    import os, uuid, requests

    def upload_video(project_id, video_path, poster_path, idempotency_key=None):
        idempotency_key = idempotency_key or str(uuid.uuid4())
        init = requests.post(
            f"https://api.rixl.com/media/v1/projects/{project_id}/videos/upload",
            headers={"X-API-Key": os.environ["RIXL_API_KEY"], "Idempotency-Key": idempotency_key},
            json={"name": os.path.basename(video_path), "video_quality": "VIDEO_QUALITY_PRO"},
            timeout=30,
        )
        init.raise_for_status()
        data = init.json()
        with open(video_path, "rb") as f:
            requests.put(data["video_upload_url"], data=f, timeout=600).raise_for_status()
        with open(poster_path, "rb") as f:
            requests.put(data["poster_upload_url"], data=f, timeout=60).raise_for_status()
        return data["video_id"]
    ```

## Retries and Idempotency

Retry the upload request only with the same `Idempotency-Key`, and only on the transient failures listed in [Retries](/en/home/platform/api-documentation/error-handling#retries): a network error, `502`, `503`, `504`, or a `409` with `Retry-After`. A retry with the same key returns the same `video_id` and URLs instead of creating a second video. Never retry a `400`, `401`, `403` or `404`.

```javascript
async function uploadVideoWithRetry(projectId, video, poster) {
  // Generate the key once, outside the loop, so every attempt reuses it.
  const idempotencyKey = crypto.randomUUID();
  for (let attempt = 0; ; attempt++) {
    try {
      return await uploadVideo(projectId, video, poster, idempotencyKey);
    } catch (error) {
      const transient =
        error.status === undefined || [502, 503, 504].includes(error.status) || (error.status === 409 && error.retryAfter != null);
      if (!transient || attempt === 3) throw error;
      const delay = error.retryAfter ? Number(error.retryAfter) * 1000 : Math.random() * Math.min(8000, 500 * 2 ** attempt);
      await new Promise((r) => setTimeout(r, delay));
    }
  }
}
```

`PUT`s to the presigned URLs replace the same object, so they are safe to retry until `expires_at`. After that, start a new upload with a new key.

## Implementation Best Practices

### Quality Tier Selection

Pick `video_quality` per video: `VIDEO_QUALITY_BASIC` for standard web content, `VIDEO_QUALITY_SHORTS` for vertical or mobile-first clips, and `VIDEO_QUALITY_PRO` for 4K or premium content. See [Quality Tiers](/en/home/platform/uploads/videos/quality-tiers).

### Batch Uploads

Upload several videos with bounded concurrency rather than all at once, each with its own `Idempotency-Key`:

```javascript
async function uploadAll(projectId, items, concurrency = 3) {
  const results = [];
  const queue = [...items];
  await Promise.all(
    Array.from({length: concurrency}, async () => {
      for (let item = queue.shift(); item; item = queue.shift()) {
        results.push(await uploadVideoWithRetry(projectId, item.video, item.poster));
      }
    })
  );
  return results;
}
```

## Troubleshooting

| Symptom                                                     | Cause                                                  | Fix                                                                                           |
| ----------------------------------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `401` on the upload request                                 | Missing or revoked API key                             | Check the `X-API-Key` header; see [API Keys](/en/home/platform/api-documentation/api-keys)    |
| `403` on the upload request                                 | The key may not access this project                    | Use the project the key was created in                                                        |
| `400` "Idempotency-Key was reused with a different request" | The same key was sent with a different body or project | Use a new key per logical upload                                                              |
| `403` from the presigned URL                                | The URL expired                                        | Start a new upload with a new key                                                             |
| Video stuck in `FILE_STATUS_UPLOADING`                      | The `PUT` never completed                              | Check the `PUT` returned `2xx`                                                                |
| `FILE_STATUS_ERROR`                                         | Processing failed                                      | See [Monitoring Status](/en/home/platform/uploads/videos/monitoring-status#handling-failures) |
