After you `PUT` a video to its upload URL, RIXL processes it in the background. Poll the video until its file status is final.

## Status Types

`GET /media/v1/videos/{video_id}` returns `{"video": {...}}`. Read `video.file.status`:

| Status                                            | Meaning                                   |
| ------------------------------------------------- | ----------------------------------------- |
| `FILE_STATUS_UPLOADING`                           | Upload URLs issued; waiting for the bytes |
| `FILE_STATUS_UPLOADED`                            | Upload received; waiting for processing   |
| `FILE_STATUS_PROCESSING`, `FILE_STATUS_PREPARING` | Being transcoded and packaged             |
| `FILE_STATUS_READY`                               | Ready to stream                           |
| `FILE_STATUS_ERROR`                               | Processing failed                         |

Clients must ignore status values they don't recognise and keep polling, as new values may be added within v1 (see [Versioning](/en/home/platform/api-documentation/versioning)).

```bash
curl "https://api.rixl.com/media/v1/videos/{videoId}" \
  -H "X-API-Key: YOUR_PROJECT_API_KEY"
```

## Polling

Poll every 5–10 seconds, back off on transient errors as described in [Retries](/en/home/platform/api-documentation/error-handling#retries), and give up after a timeout that fits your file sizes and quality tier.

<Tabs items={['TypeScript', 'Python']}>
  <Tab value="TypeScript">
    ```typescript
    type FileStatus = string;

    async function waitUntilReady(videoId: string, timeoutMs = 30 * 60_000): Promise<FileStatus> {
      const deadline = Date.now() + timeoutMs;
      while (Date.now() < deadline) {
        const response = await fetch(`https://api.rixl.com/media/v1/videos/${videoId}`, {
          headers: {"X-API-Key": process.env.RIXL_API_KEY!},
        });
        if (response.ok) {
          const status: FileStatus | undefined = (await response.json()).video?.file?.status;
          if (status === "FILE_STATUS_READY" || status === "FILE_STATUS_ERROR") return status;
        } else if (![502, 503, 504].includes(response.status) && !response.headers.has("Retry-After")) {
          throw new Error(`status check failed: ${response.status}`);
        }
        const retryAfter = Number(response.headers.get("Retry-After") ?? 0);
        await new Promise((r) => setTimeout(r, Math.max(retryAfter * 1000, 5000)));
      }
      throw new Error(`video ${videoId} not ready after ${timeoutMs} ms`);
    }
    ```

  </Tab>

  <Tab value="Python">
    ```python
    import os, time, requests

    def wait_until_ready(video_id: str, timeout_s: int = 1800) -> str:
        deadline = time.monotonic() + timeout_s
        while time.monotonic() < deadline:
            r = requests.get(
                f"https://api.rixl.com/media/v1/videos/{video_id}",
                headers={"X-API-Key": os.environ["RIXL_API_KEY"]},
                timeout=30,
            )
            if r.ok:
                status = r.json().get("video", {}).get("file", {}).get("status")
                if status in ("FILE_STATUS_READY", "FILE_STATUS_ERROR"):
                    return status
            elif r.status_code not in (502, 503, 504) and "Retry-After" not in r.headers:
                r.raise_for_status()
            time.sleep(max(int(r.headers.get("Retry-After", 0)), 5))
        raise TimeoutError(f"video {video_id} not ready after {timeout_s}s")
    ```

## Handling Failures

<Callout type="warn" title="FILE_STATUS_ERROR is final">
  A failed video does not recover by polling. Start a new upload with a new `Idempotency-Key`; reusing the old key replays the failed
  upload's URLs.
</Callout>

Common causes:

- **Unsupported input** - check [supported formats](/en/home/platform/uploads/videos/supported-formats).
- **Corrupt or truncated upload** - verify the `PUT` returned `2xx` and sent the whole file.
- **Expired upload URL** - the `PUT` must start before the upload response's `expires_at`.
