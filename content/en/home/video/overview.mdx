## Video Pipeline Architecture

When a video is uploaded, it transitions through distinct processing states:

1. **Upload Initiation** – The client requests an upload reservation and receives an authorized direct upload URL.
2. **Direct Ingestion** – Binary media is streamed directly to secure storage via HTTP `PUT`.
3. **Automated Encoding** – RIXL inspects source dimensions, audio tracks, and codecs, producing optimized renditions according to the chosen tier.
4. **Active Delivery** – The HLS playlist and assets become immediately available via the edge network.

For comprehensive state descriptions and error handling, see [Monitoring Status](/en/home/video/monitoring-status).

### Direct API Upload Workflow

<Tabs items={['Two-Step Direct Upload', 'Query Status']}>
  <Tab value="Two-Step Direct Upload">
    ```javascript
    // Step 1: Request upload authorization
    const initResponse = await fetch(
      `https://api.rixl.com/media/v1/projects/${projectId}/videos/upload`,
      {
        method: 'POST',
        headers: {
          'X-API-Key': apiKey,
          'Content-Type': 'application/json'
        },
        body: JSON.stringify({
          name: videoFile.name,
          video_quality: 'VIDEO_QUALITY_PRO'
        })
      }
    );

    const {video_id, video_upload_url} = await initResponse.json();

    // Step 2: Stream binary file to direct upload URL
    await fetch(video_upload_url, {
      method: 'PUT',
      headers: {
        'Content-Type': videoFile.type || 'video/mp4'
      },
      body: videoFile
    });

    console.log('Upload complete, processing video ID:', video_id);
    ```

  </Tab>

  <Tab value="Query Status">
    ```javascript
    const response = await fetch(
      `https://api.rixl.com/media/v1/videos/${videoId}`,
      {
        headers: {'X-API-Key': apiKey}
      }
    );

    const {video} = await response.json();
    console.log('Video state:', video.file.status);
    console.log('Playback URL:', video.file.url);
    ```

  </Tab>
