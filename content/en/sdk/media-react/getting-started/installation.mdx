## Requirements

Before installing the RIXL Media SDK for React, ensure your project meets these requirements:

- **React**: 18.0 or higher
- **Node.js**: 24.0 or higher
- **TailwindCSS**: 4.0.9 or higher _(recommended but optional)_

## Setting Up Your First Video

### 1. Upload Your Media

Before using the SDK, you need to upload your media content:

<Steps>
  <Step>
    **Upload to Dashboard**

    Go to [dash.rixl.com/videos](https://dash.rixl.com/videos) for videos or [dash.rixl.com/images](https://dash.rixl.com/images) for images

  </Step>
  <Step>
    **Get Media ID**

    Copy the generated media ID (e.g., `"FU9aVtA88m"`)

  </Step>
  <Step>
    **Authenticate and Render**

    Call `connect()` if your app is standalone, then reference the media ID in your React components

  </Step>
</Steps>

### 2. Import the Components

```tsx
import {Video, Image, Feed} from "@rixl/media-react";
```

### 3. Authenticate the SDK

All media fetches go through the shared `@rixl/sdk` HTTP client. Choose the mode that matches your app:

**Embedded mode** — your host app already calls `@rixl/sdk`'s `connect()` for its own API calls. The media SDK will automatically use the same authenticated client, so you do not need to do anything extra.

**Standalone mode** — call `connect()` once, before rendering any media component, to exchange your API key for a Bearer token:

```tsx
import {connect} from "@rixl/media-react";

await connect({
  baseUrl: "https://api.rixl.com",
  apiKey: "your-rixl-api-key",
});
```

`connect` is re-exported from `@rixl/media-react` for convenience — components, hooks, upload helpers, analytics, and stores all come from this single package.

### 4. Use in Your Component

```tsx
import {Video} from "@rixl/media-react";

function App() {
  return (
    <div className="container mx-auto p-4">
      <h1>My First RIXL Video</h1>
      <Video id="D3OCjdLP60" className="w-full h-auto rounded-lg" analyticsPage="standalone" />
    </div>
  );
}
```

<Callout type="info">
  Need custom controls instead of the built-in player UI? Use the public [Hooks](/en/sdk/media-react/hooks) inside a `<VideoPlayer>` scope. The player-scope hooks bind to the enclosing player scope, not directly to `<Video>`.
</Callout>

## Server-Side Rendering (Next.js / TanStack Start)

The same `@rixl/media-react` package works with SSR — no separate wrapper, adapter plugin, `ssr: false` wrapper, or `<ClientOnly>` needed. The `/core` entry remains usable on the server.

During SSR or static prerendering, React renders the `<rixl-image>`, `<rixl-video>`, and `<rixl-feed>` host tags and any children you supply. In the browser, React restores component properties and Lit renders their shadow DOM. The inner `<img>`, `<video>`, player controls, and feed items are **not rendered into the initial server HTML** — JavaScript is required to display and operate them.

Passing `imageData`, `videoData`, or `posts` from a server loader avoids an additional media-data request in the browser. Set component dimensions or an aspect ratio for stable page layout, and render essential page text and metadata in your application when they must be present in the initial HTML.

### Next.js App Router

The public UI entries preserve `"use client"`, so a Server Component can import components directly:

```tsx
// app/page.tsx — Server Component
import {Image} from "@rixl/media-react/image";
import type {ImageData} from "@rixl/media-react/core";
import {loadImageData} from "./data";

export default async function Page() {
  const imageData: ImageData = await loadImageData();
  return <Image imageData={imageData} analytics={false} alt="Mountain landscape" />;
}
```

Pass serializable data across the server/client boundary. Event handlers, refs, and player hooks belong in your own `"use client"` components. When loading media by ID, initialize the shared SDK in a client component and await `connect` before mounting the media components. Only send credentials intended for client use to the browser.

### TanStack Start

Use your normal TanStack Start configuration — no Rixl-specific `ssr.noExternal` setting or CSS import is needed:

```tsx
// src/routes/media.tsx
import {createFileRoute} from "@tanstack/react-router";
import {Image} from "@rixl/media-react/image";
import {loadImageData} from "../data";

export const Route = createFileRoute("/media")({
  loader: () => loadImageData(),
  component: MediaPage,
});

function MediaPage() {
  const imageData = Route.useLoaderData();
  return <Image imageData={imageData} analytics={false} alt="Mountain landscape" />;
}
```

Use a server function when the loader needs private credentials. If components fetch by ID or send analytics, initialize the shared SDK in the browser before mounting them.

## Styling Setup (Optional)

### With TailwindCSS

If you're using TailwindCSS (recommended), the examples above will work out of the box. Ensure TailwindCSS is properly configured in your project.

Component styles live inside their shadow DOM — the SDK builds no global stylesheet and your app needs no CSS import for the player UI. When migrating from the older React UI, remove `import "@rixl/media-react/style.css"`; that entry is no longer exported.

### Without TailwindCSS

You can use regular CSS classes or CSS-in-JS solutions:

```tsx
// Using regular CSS classes
<Video
  id="D3OCjdLP60"
  className="custom-video-player"
/>

<Image
  id="hero-image"
  className="custom-image"
/>
```

```css
/* styles.css */
.custom-video-player {
  width: 100%;
  height: auto;
  border-radius: 8px;
  box-shadow: 0 4px 6px rgba(0, 0, 0, 0.1);
}

.custom-image {
  width: 100%;
  height: auto;
  object-fit: cover;
}
```
