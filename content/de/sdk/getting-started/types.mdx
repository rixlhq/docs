## Component Props

### VideoProps

```typescript
interface VideoProps extends Omit<HTMLProps<HTMLVideoElement>, "onEnded"> {
  id: string;
  src?: string;
  autoPlay?: boolean;
  muted?: boolean;
  analytics?: boolean;
  analyticsPage?: Page;
  feedId?: string;
  postId?: string;
  isCurrent?: boolean;
  onRixlAnalytics?: (event: CustomEvent<{event: AnalyticsEvent}>) => void;
}

// `VideoTheme` wird weiterhin von `@rixl/media` für Settings/Caption-Styling exportiert,
// aber der React `<Video>`-Wrapper akzeptiert kein `theme`-Prop mehr.
type VideoTheme = "default" | "minimal" | "hover" | "feed" | "hideUI";

type SupportedLanguage = "en" | "de" | "es" | "fr" | "it" | "pl" | "ru" | "tr" | "uk";

type Page = "feed" | "standalone" | "profile";
```

`VideoProps` erbt außerdem die meisten Standard-HTML-Video-Props wie `className`, `muted`, `autoPlay`, `playsInline` und die meisten DOM-Event-Handler. `loop` wird akzeptiert, aber aktuell nicht an das Lit-Element weitergegeben. `onEnded` ist nicht Teil der öffentlichen `<Video />`-Props; für den End-of-Playback-Status kannst du `onRixlAnalytics` verwenden oder die Player-Scope-Hooks mit `<VideoPlayer>` nutzen.

### VideoPlayerProps

```typescript
interface VideoPlayerProps {
  children?: ReactNode;
}
```

`VideoPlayer` erstellt einen Player-Scope für detached Controls. Render Hook-Consumer als Geschwister von `<Video>` innerhalb von `<VideoPlayer>`, um den Zustand zu teilen. Das neue Lit-basierte `<Video>` registriert sich nicht automatisch in den legacy Player-Stores; benutzerdefinierte Controls mit Hooks müssen explizit an einen Player-Scope angebunden werden.

## Hook Types

### Player-Scoped Hooks

Diese Hooks lesen den Zustand aus dem umgebenden Player-Scope. Rufe sie in einer Komponente auf, die als Kind von `<VideoPlayer>` gerendert wird. Sie nehmen keine Argumente und binden an den aktuellen Player-Scope. Beachte, dass das neue Lit-basierte `<Video>` ein selbstständiges Custom Element ist und nicht automatisch am Player-Scope teilnimmt; benutzerdefinierte Controls sollten daher als Geschwister innerhalb von `<VideoPlayer>` gebaut werden oder `onRixlAnalytics` nutzen, um auf Player-Events zu reagieren.

To pause every other player relative to the current scope, use the scoped `pauseOthers()` returned from [`usePlayback()`](/de/sdk/hooks/use-playback).

### DOM Progress Helper

`useProgressBar` is a lower-level hook for a raw `HTMLVideoElement`. For the public `Video` component, prefer `usePlayerProgress()` when building custom controls.

```typescript
interface UseProgressBarProps {
  video: HTMLVideoElement | null;
}

declare function useProgressBar(props: UseProgressBarProps): {
  progress: number;
  isDragging: boolean;
  handleDragStart: (event: MouseEvent | TouchEvent) => void;
};
```

### Hinweise zum Wire-Format

- `postAnalytics` queued Events und flushed sie in einem Micro-Task.
- Der erste Flush fügt automatisch ein `session_start`-Event voran.
- Alle Millisekunden-Dauern werden in `GoogleProtobufDuration`-Strings (`"5s"`, `"1.234s"`) umgewandelt, bevor sie an `/analytics/v1/events` gesendet werden.
- `content_type` wird als `MEDIA_TYPE_IMAGE` oder `MEDIA_TYPE_VIDEO` übertragen.
